# Environment variable registry

Required to run `/admin` and the contact form: `PAYLOAD_SECRET` and `DATABASE_URI` (the public pages still build without them). `TURNSTILE_SECRET_KEY` and `RESEND_API_KEY` + `CONTACT_TO_EMAIL` are read by the Folio contact path. If `TURNSTILE_SECRET_KEY` is missing in production the contact form **fails closed**: submissions are rejected with an error and nothing is sent (it never skips the check). Never commit values. Local values live in `.env.local` (ignored by git); the lead copies them into worktrees. Names starting with `NEXT_PUBLIC_` are inlined into the browser bundle, so never put secrets in them.

CI (GitHub Actions) currently needs no secrets. Lighthouse CI uses temporary public storage and needs no token. `.github/workflows/ci.yml` sets no `DATABASE_URI` or `PAYLOAD_SECRET` on purpose: with no database every job builds and tests against the static content fallback (`lib/data.ts`), so CI never touches Atlas. A DB-backed job (for example `mongodb-memory-server` plus a seed) is a Phase 4 suggestion only, to cover the live-edit path that the static jobs cannot.

Step-by-step account and secret setup: `docs/ops/accounts.md`. Never paste secret values into chat or commit them.

Read but never set by us: `VERCEL` (`1` on Vercel: gates the Secure session cookie in `collections/Users.ts`, the trusted IP headers in `lib/rate-limit.ts` and the allowlist in `lib/origins.ts`), `VERCEL_ENV` (`production` / `preview` / `development`: gates `components/shared/Telemetry.tsx`, analytics only render when it is `production`; closes the first-user sign-up in `collections/Users.ts` unless `ALLOW_FIRST_USER=1`; sets Payload `serverURL` only in production), `VERCEL_URL`, `VERCEL_BRANCH_URL`, `VERCEL_PROJECT_PRODUCTION_URL` (Vercel system variables, for `metadataBase` and the origin allowlist), `NODE_ENV` (Next sets it; outside production the Turnstile check is skipped when no secret is set, in production it fails closed) and `PORT` (local fallback only). `NEXT_DIST_DIR` is read in `next.config.ts`; `DATABASE_URI`, `PAYLOAD_SECRET` and `BLOB_READ_WRITE_TOKEN` in `payload.config.ts` (without the Blob token uploads fall back to local disk, which does not persist on Vercel). Keep "Automatically expose System Environment Variables" on in Vercel > Settings > Environment Variables (the default).

## Vercel scopes

Vercel has three scopes per variable: Production (pushes to `main`), Preview (every other branch and PR), Development (`vercel dev`/`vercel env pull`). A change only applies to deployments built after it, so redeploy. The click-by-click steps are in `docs/ops/vercel-setup.md`. Config type is fine for the variables above; use Secret type for everything marked Secret.

## Rules

- Add a new variable here in the same change that starts reading it.
- Production values are set only by Akash in the Vercel dashboard (Settings > Environment Variables). Agents prepare the name and instructions, not the value.
- Use different `PAYLOAD_SECRET` and database users for Production and Preview.
- Error reporting must not include PII: scrub emails and message bodies from the contact form before events leave the server.
- Cloudflare publishes always-pass test keys for Turnstile; use those locally and in e2e.
