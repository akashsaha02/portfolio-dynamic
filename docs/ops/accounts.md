# Free account setup (about 15 minutes)

Everything here is free. Do these by hand: agents never create accounts or touch your dashboards. **Never paste a secret into chat, an issue, a PR or a commit.** Secrets go only into `.env.local` (git-ignored) and the Vercel dashboard. If an agent needs a value changed, tell the lead "it is set", not the value.

UI labels below were checked against the vendors' docs on 2026-10-15; dashboards move things around, so match by name, not position.

Sources: [Atlas free cluster limits](https://www.mongodb.com/docs/atlas/reference/free-shared-limitations/), [Atlas getting started](https://www.mongodb.com/docs/atlas/getting-started/), [Vercel Blob](https://vercel.com/docs/vercel-blob), [Blob pricing/limits](https://vercel.com/docs/vercel-blob/usage-and-pricing), [Resend pricing](https://resend.com/pricing), [Turnstile dashboard widgets](https://developers.cloudflare.com/turnstile/get-started/widget-management/dashboard/), [Turnstile test keys](https://developers.cloudflare.com/turnstile/troubleshooting/testing/).

## 1. MongoDB Atlas (database)

Free cluster limits: 0.5 GB data+index storage, 500 connections, 100 ops/second, one free cluster per Atlas project, no backups, auto-pauses after 30 days with zero connections (resume it in the Atlas UI; a live site keeps it awake).

1. Sign up at https://www.mongodb.com/cloud/atlas/register (Google/GitHub login is fine). Create an organization and a project named `portfolio`.
2. **Create a cluster** (or Build a Database) and choose the **Free** tier. Provider **AWS**, region **N. Virginia (us-east-1)**: it sits next to Vercel's default function region `iad1`, which matters more for latency than being near Dhaka (the database is only read at build or by the admin/contact form, not by visitors). If the UI offers a Singapore region and you will mostly use the admin from Bangladesh, you may pick it, but keep the Vercel function region in mind: the two should be close to each other. Name it `portfolio`. Skip sample data.
3. **Database access** (Security > Database Access > Add New Database User). Create **two** users with **Password** authentication, using the "Autogenerate Secure Password" button and copying it straight into your password manager:
   - `portfolio-dev`: built-in role **Read and write to any database** is the least the UI offers by default; better, choose **Specific Privileges** and grant `readWrite` on database `portfolio-dev` only.
   - `portfolio-prod`: **Specific Privileges**, `readWrite` on database `portfolio` only.
   - Do not use `atlasAdmin` (the wizard's default) for either.
   - Preview deployments use the dev database/user (`portfolio-dev`) so a test branch can never touch production content.
4. **Network access** (Security > Network Access > Add IP Address). Vercel functions have no fixed IPs on Hobby, so you must add **0.0.0.0/0 (Allow access from anywhere)**. Tradeoff: anyone on the internet can attempt to connect. Mitigations, all of which you are doing: a long random password, TLS-only connections (Atlas default), per-database least-privilege users, no `atlasAdmin` user, and nothing else in the cluster worth stealing. Delete any "my current IP" entries once 0.0.0.0/0 exists, so the list is clean.
5. **Connection string** (Database > Connect > Drivers). Copy the `mongodb+srv://` string and put the database name before the `?`:

   ```
   mongodb+srv://portfolio-prod:<password>@<cluster-host>.mongodb.net/portfolio?retryWrites=true&w=majority&appName=portfolio
   ```

   Dev uses the same host with `portfolio-dev:<dev-password>` and `/portfolio-dev`. URL-encode special characters in the password (or use the autogenerated one and avoid `@ : / ?`).
6. Optional alerts: Project > Alerts, add one for Logical Size at 350 MB (see `docs/ops/free-tier.md`).

## 2. Vercel Blob (uploaded images)

Hobby free limits: 1 GB storage, 10,000 simple operations, 2,000 advanced operations (uploads, list), 10 GB blob data transfer per month. Past a limit, Blob stops working for 30 days; you are not billed. Using the Blob file browser in the dashboard also counts as operations.

1. Sign in at https://vercel.com (Hobby plan) and import the GitHub repo as a project if you have not (see `docs/ops/vercel-setup.md`).
2. Dashboard > project > **Storage** tab > **Create Database / Create Store** > **Blob**.
3. Choose **Public** access (portfolio images are public and `next/image` reads them by URL). **The access mode cannot be changed after creation.** Region: same as the project's function region (`iad1`, Washington D.C.); the store region cannot be changed either.
4. Name it `portfolio-media` and create it. Connect it to the project for **Production and Preview** (store > **Projects** tab > **Connect to Project**).
5. Vercel adds `BLOB_READ_WRITE_TOKEN` to the project when the store is created (it also adds `BLOB_STORE_ID` and OIDC variables; leave those alone). Payload's browser uploads need the read-write token, so keep it.
6. For local dev, either run `npx vercel env pull .env.local` once after `npx vercel link` (needs the Vercel CLI login; this writes all connected variables, so re-add any local-only ones), or open the store > **.env.local** tab and copy only `BLOB_READ_WRITE_TOKEN`. Using the production store from local dev means local uploads land in production storage; acceptable for a one-person site, otherwise create a second store `portfolio-media-dev` and connect it to Development only.

## 3. Resend (contact-form email)

Free limits: 100 emails/day, 3,000/month, 3 domains (Resend pricing page). No card needed.

1. Sign up at https://resend.com with the email address that should receive contact messages (`akash@nyntax.com`, or whichever you want).
2. **API Keys** > **Create API Key**. Name `portfolio-prod`, permission **Sending access** (not Full access), domain **All domains** for now. Copy the key (`re_...`) immediately; it is shown once. Optionally create a second key `portfolio-dev` for `.env.local`.
3. Until you verify a domain, send from `onboarding@resend.dev` and send **to your own account email only**. Resend's shared testing sender can deliver only to the email address that owns the Resend account, so `CONTACT_TO_EMAIL` must equal the address you signed up with. (This is the documented behaviour for the test sender at the time of writing; if a send is rejected, this is the first thing to check.)
4. Later, to send from your own domain or to other recipients: Resend > **Domains** > **Add Domain**, enter e.g. `mail.yourdomain.com`, add the SPF, DKIM (and optional DMARC) DNS records Resend lists at your registrar, wait for the status to turn **Verified**, then change the sender (config in code, backend will name the variable) and rotate nothing. A domain costs money, so this is optional for a $0 setup.

## 4. Cloudflare Turnstile (spam protection)

Free, no card. Up to 20 widgets.

1. Sign up at https://dash.cloudflare.com/sign-up (no domain needed). Open **Turnstile** in the left menu.
2. **Add widget**:
   - **Widget name**: `portfolio`.
   - **Hostname management**: add your production hostname(s): `<project>.vercel.app` and any custom domain. Add preview domains too if you want the form to work on previews (`*.vercel.app` wildcard is not accepted as a wildcard by every plan; if it is rejected, add the specific preview host or use the test keys on previews). `localhost` is not needed for local work because the Cloudflare test keys (below) work on any host; production site keys should not allow local domains.
   - **Widget mode**: **Managed**.
   - Leave Pre-clearance off.
3. **Create**. Copy the **Site key** (public) and **Secret key** (private, shown once on this screen; it can be regenerated later).
4. Local dev and e2e use Cloudflare's always-pass test keys instead of real ones: site key `1x00000000000000000000AA`, secret key `1x0000000000000000000000000000000AA`. Real keys go in Vercel only (Production, and Preview if wanted).

## 5. Secrets you generate yourself

`PAYLOAD_SECRET` signs admin sessions. Generate one per environment (local, Preview, Production), never reuse:

```bash
openssl rand -base64 32
# no openssl? use Node:
node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"
```

Copy the output straight into `.env.local` or the Vercel field. Do not echo it into a shared terminal log or paste it anywhere else.

## 6. Bootstrap the admin (do this BEFORE `DATABASE_URI` exists on Vercel)

Payload sends anyone who opens `/admin` on an empty database to the first-register screen, and the first account created wins (the single-user hook then refuses everyone else, you included). So the admin must exist before the production database is reachable from a public deployment. Previews sit behind Vercel Authentication; Production does not.

1. Pick a **login email that is not published on the site** (not `akashsaha1313@gmail.com`). The 5-failed-logins lockout is per account, so anyone who knows the login email can keep you locked out. A separate alias or a plain unused address is fine; it never needs to receive mail (no email adapter is configured).
2. Generate a long unique password in your password manager. Never reuse one, and never paste it into chat.
3. From **your own machine**, in the repo root, with `.env.local` temporarily pointing `DATABASE_URI` at the Atlas **production** database (`.../portfolio` as `portfolio-prod`) and a `PAYLOAD_SECRET`, run the seed with the admin values set only for this command:

   ```bash
   SEED_ADMIN_EMAIL='you+admin@example.com' SEED_ADMIN_PASSWORD='<from password manager>' npm run seed
   ```

   (PowerShell: set `$env:SEED_ADMIN_EMAIL` and `$env:SEED_ADMIN_PASSWORD`, run `npm run seed`, then remove both.) Check `package.json` for the exact seed script name. Afterwards restore `.env.local` to the dev database.
4. Only now add `DATABASE_URI` and `PAYLOAD_SECRET` to Vercel Production, deploy, and log in at `/admin`.
5. On Vercel (`VERCEL_ENV` set) the backend guard refuses `first-register` while the collection is empty, so an empty database is a "no admin" state, not an open door. To deliberately create the first user on a Vercel deployment set `ALLOW_FIRST_USER=1` for that one deployment and remove it right after. Locally the first-register screen still works.

## 7. Recover the admin

There is no email adapter, so "forgot password" sends nothing. Recovery needs database access from your machine:

```bash
npm run admin:reset-password
```

Run it with `.env.local` pointing at the target database (production: `portfolio` as `portfolio-prod`); the script's own prompts or variables are described at the top of `scripts/reset-admin-password.ts`. Then log in with the new password.

Lockout: 5 failed logins lock the account for 15 minutes, even with the right password. Wait it out. If it keeps happening for no reason, someone knows the login email: change the admin email to an unpublished one with the reset script and rotate `PAYLOAD_SECRET` (ends all sessions).

## 8. Which host the admin works on (silent failure)

The admin cookie is accepted only for origins in the allowlist (`lib/origins.ts`, fed to Payload `csrf`/`cors`). Open `/admin` on any other host and **it fails silently**: the login request returns 200, but the cookie is ignored, so you land back on the login page with no error.

- **Production**: the admin works on the main production domain (`NEXT_PUBLIC_SITE_URL`, else Vercel's production URL), plus that deployment's own URL and branch URL. Any other alias (a second custom domain, the `*.vercel.app` alias when a custom domain is primary) does not work for the admin until you add it to `EXTRA_ALLOWED_ORIGINS` (comma-separated, max 5, `https://host` only) in Vercel and redeploy.
- **Preview**: the admin works on that deployment's URL and branch URL. Preview deployments are behind Vercel Authentication, so you also need to be signed in to Vercel.
- **Local**: `http://localhost:3000` and `http://127.0.0.1:3000` work. Testing the admin or site on a **real phone over Wi-Fi** does not, unless you allow the laptop's address:

  ```bash
  # .env.local (use your laptop's LAN IP; the port must match)
  EXTRA_ALLOWED_ORIGINS=http://192.168.1.23:3000
  # start the dev server on all interfaces
  npx next dev -H 0.0.0.0
  ```

  Then open `http://192.168.1.23:3000/admin` on the phone. Remove the variable afterwards; do not set a LAN origin on Vercel. If Windows Firewall asks, allow Node on private networks only.
- Symptom checklist: login returns 200 and nothing happens, saves do nothing, or you are logged out immediately. First check the address bar host against the lists above.

## 9. Ably (optional: live visitors, reactions, cursors)

Only when you want realtime (work plan 6.5/6.9). Without this key the site builds and runs exactly as before, with no realtime code shipped. Free package: no card, no time limit; limits and what uses them in `docs/ops/free-tier.md` ("Ably: what eats the quota").

1. Sign up at https://ably.com (free). Create an app named `portfolio` (any region; leave defaults: no persistence, no integrations, no extra channel rules or namespaces needed).
2. App > **API Keys**. Either copy the **Root** key, or (safer) **Create a new API key** named `portfolio-server` with only **Publish**, **Subscribe** and **Presence** on resource `*` (no History, Stats, Push or Channel metadata). Browsers never see this key: the server signs 1-hour tokens with narrower rights from it, and a token can't have more rights than its key.
3. Copy the **full** key (`appId.keyId:secret`, including the colon and the secret) into your password manager.
4. Vercel > Settings > Environment Variables: `ABLY_API_KEY` = the key, **Production** only, Sensitive on. Then **redeploy**: the key is checked at build time to switch realtime on. Reactions also need `DATABASE_URI` in the same scope.
5. Local testing (optional): create a second app `portfolio-dev` and put its key in `.env.local`, so local runs never count against production stats (channel names already differ per environment).
6. Check after a day: app > **Stats** (messages, peak connections). Add a Usage log row in `free-tier.md` at the monthly check.

To turn realtime off: delete `ABLY_API_KEY` in Vercel and redeploy. To rotate: create a new key, swap it in Vercel, redeploy, then revoke the old key in Ably.

## Where each value goes

Local file is `.env.local` in the repo root (git-ignored, never committed). Vercel: Project > Settings > Environment Variables; for each variable tick the environments shown. GitHub secrets are not needed yet (CI builds without secrets).

| Variable | Dev value | Local `.env.local` | Vercel Preview | Vercel Production | GitHub secret |
| --- | --- | --- | --- | --- | --- |
| `PAYLOAD_SECRET` | random, unique | yes | yes (different random) | yes (different random) | no |
| `DATABASE_URI` | `.../portfolio-dev` as `portfolio-dev` | yes | yes (dev string) | yes (`.../portfolio` as `portfolio-prod`) | no |
| `BLOB_READ_WRITE_TOKEN` | from store | yes | auto (store connected) | auto (store connected) | no |
| `RESEND_API_KEY` | `portfolio-dev` key | yes | yes | yes | no |
| `CONTACT_TO_EMAIL` | your Resend account email | yes | yes | yes | no |
| `NEXT_PUBLIC_TURNSTILE_SITE_KEY` | test key `1x00000000000000000000AA` | yes | real or test key | real key | no |
| `TURNSTILE_SECRET_KEY` | test secret `1x0000000000000000000000000000000AA` | yes | real or test secret | real secret | no |
| `ABLY_API_KEY` (optional) | `portfolio-dev` app key, or unset | optional | normally unset | `portfolio` app key | no |

Mark every variable except `NEXT_PUBLIC_TURNSTILE_SITE_KEY` as **Sensitive** when Vercel offers the toggle (value hidden after save). Names are the canonical list in `docs/ops/env.md`.

## If a secret leaks

Treat any secret that appeared in chat, a commit, a screenshot or a log as leaked. Rotate in this order, then redeploy (Vercel only applies changes to new deployments):

1. **Git history**: if it was committed, rotate anyway; deleting the commit does not unleak it.
2. `PAYLOAD_SECRET`: generate a new one, replace in Vercel and `.env.local`. All admin sessions end; log in again.
3. `DATABASE_URI`: Atlas > Database Access > the user > **Edit** > **Edit Password** (autogenerate), update the string in Vercel and `.env.local`. If unsure what was read, also delete and recreate the user.
4. `BLOB_READ_WRITE_TOKEN`: Vercel > Storage > the store > settings > regenerate the read-write token (it updates the connected project; run `vercel env pull` locally).
5. `RESEND_API_KEY`: Resend > API Keys > delete the key, create a new one, update Vercel and `.env.local`.
6. `TURNSTILE_SECRET_KEY`: Cloudflare > Turnstile > the widget > rotate the secret key, update Vercel.
7. `ABLY_API_KEY`: Ably > the app > API Keys > create a new key with the same rights, swap it in Vercel, redeploy, then **Revoke** the old key (existing browser tokens die within an hour).
8. Check the usage pages (`docs/ops/free-tier.md`) for unexpected spikes over the next days.
