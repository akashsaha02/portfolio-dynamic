# Phase 2 gate (task 2.G): backend and admin

Date: 2026-10-15. Auditor: qa agent. Build audited: `main` at `25f1e5c` (tasks 2.1–2.8 merged).

**Environment**

- **Database:** in-memory MongoDB from `npm run dev:db` (replica set, port 27651).
- **Secrets:** `PAYLOAD_SECRET` was a random 32-byte value.
- **Admin account:** `qa-admin@example.com`, seeded with `npm run seed`. The password is 19 characters and was used only on this throwaway database.
- **Turnstile:** Cloudflare's test secret `1x0000000000000000000000000000000AA` (always passes).
- **Servers** (all `next start`, Folio build, `SITE_TEMPLATE=folio NEXT_DIST_DIR=.next-folio`):
  - `:3650` on the seeded database `portfolio`. Main audit server.
  - `:3651` on an empty database `qafresh`. Used for the first-register re-run.
  - `:3652` with the always-fail secret `2x0000000000000000000000000000000AA`.
  - `:3653` with no Turnstile secret, to check that a production build fails closed.

Everything was stopped afterwards. The QA run's own artifacts were removed: the seed's `./media` folder and a canary build. Both `.next*` folders were rebuilt clean by the final e2e run.

Tools and raw data are kept for the tester (task 4.3):

- Scripts: `docs/qa/phase-2/tools/`
- Logs and data: `docs/qa/phase-2/data/`
- Screenshots: `docs/qa/phase-2/screens/` (WebP, 25 files, 479 KB)

## Verdict: FAIL

There are **1 blocker, 4 major and 13 minor** findings.

The backend's security core is solid. Every item below was verified against a running build, not just read in the code:

- **Access rules:**
  - Anonymous visitors cannot read, count, version, query, or write `messages`, `users` or `rate-limits`.
  - No draft content leaks through any REST path. 38 operations × 12 collections were checked, plus 20 draft probes.
  - GraphQL is gone.
- **Admin account:**
  - The single-user rule holds.
  - Login lockout works.
  - Logout revokes the token.
- **Server Actions:** both actions re-check auth and reject foreign `Origin` headers.
- **Contact action:**
  - Validation works and the honeypot answers "success".
  - Turnstile fails closed in all three bad configurations.
  - The 5/hour and 20/day limits trip exactly at the 6th and 21st message.
  - No raw IP is stored and no PII appears in logs.
- **Media uploads:** script-bearing SVGs are rejected, MIME types are sniffed, files over 4 MB are refused, and path traversal is stripped.
- **Secrets:** no secret name or value reaches any build output. A canary build was grepped for this.
- **Seed:** it is idempotent and matches `lib/content.ts`.
- **Admin on phones:** it works at 360 and 768: dashboard, toggle, inbox filter, edit, reorder (touch and mouse), upload form and live preview.

The phase still fails, for one reason: **the e2e gate is red on `main`**. 12 Folio contact tests fail on every viewport, and failed again in a second run. The cause is task 2.5: it replaced the stub inside `lib/actions/contact.ts` in place, so the Folio form already calls the real action. In a production build without a Turnstile secret (CI, e2e), that action correctly fails closed. CI's e2e job runs the same suite, so `main` CI is red too. Phase 2 only ran typecheck and build per task (memory: "build first, test later"), which is why nobody saw it.

After that, fix the 4 majors:

- Patch Next 16.3.7 (6 advisories, one high). One of them leaks draft-mode content through `use cache`, exactly what task 3.4 builds.
- Set Payload's CSRF/CORS allowlist. Right now cookie-authenticated REST writes are accepted from any `Origin`.
- Add security headers. There are none on the site or the admin.
- Close the first-register window. On an empty production database, the first visitor to `/admin` becomes the only admin.

None of these needs a new service. The blocker plus all majors is about one backend day.

## 9. Free tier (guide §9)

- **Routes that hit the DB once Phase 3 connects:**
  - Static pages (`/`, `/work`, `/work/[slug]`, `/about`, `/contact`, OG images): only at build time and on the first request after an admin edit revalidates a tag.
  - Per request (function + Payload init + a cached or uncached read): `/resume` (`ƒ`; wrap its `getSiteContent` in the same `unstable_cache`), `/[...missing]` and `/work/<unknown>` (already in `docs/ops/free-tier.md`), `/api/draft` (session lookup), every `/api/*` REST call (F-15) and `/admin`.
  - The contact Server Action costs one Turnstile call, 1 find + 2 inserts, and a createIndex once per instance.
  - Each cold start connects to Mongo and, with `autoIndex`, re-ensures indexes (F-14).
  - No sockets on public pages; the public JS has no Payload code (§5).
- **Mongo on serverless:** one cached connection per instance (Payload caches `getPayload`). The pool is untuned (F-14). Atlas M0 caps at 500 connections, and `maxPoolSize: 5` keeps 100 warm instances inside it.
- **Blob adapter:**
  - `enabled` only with a token, and `alwaysInsertFields` keeps the schema stable (`payload.config.ts:110-115`). `disablePayloadAccessControl` means files come straight from the public Blob URL, so serving costs no function call (media is public anyway). `next.config.ts:44` allows `*.public.blob.vercel-storage.com` with no query string.
  - No `imageSizes`, so there are no extra Blob writes per upload.
  - Uploads still go through the function. Payload's 4,000,000-byte limit sits under Vercel's 4.5 MB request cap (multipart overhead is small). A larger file is cut off by Vercel first with a generic error; `docs/admin-guide.md` already says "4 MB is the hard limit".
- **New paid dependency:** none. Everything added in Phase 2 is MIT/free. The fixes above add none either: header config, overrides and Payload options. `@payloadcms/email-resend` (optional, F-12) uses the existing free Resend key.
